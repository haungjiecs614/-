# /sync —— 同步状态

目标：第 **$ARGUMENTS** 章（三位数补零，记为 XXX）

前提：作者已确认本章定稿。运行本命令即视为作者确认。

## 0. 前置检查
- `chapters/chXXX.md` 不存在 → 停止。
- state/summaries.md 中没有上一章（XXX-1）的摘要（第 1 章除外）→ 停止，提示先同步上一章。状态必须按章顺序累积。
- state/summaries.md 中已有本章摘要 → 进入**重新同步**模式：先根据 git 历史或现有条目判断上次同步写入了什么，替换而不是重复追加；在差异清单中标明"重新同步"。

## 1. 读取
- **定稿正文** `chapters/chXXX.md`（以正文为准，不以章节卡为准）
- `cards/chXXX.md`（用于发现"计划与实际不符"）
- state/ 下全部 5 个文件
- 本章出场角色的 bible/characters/*.md（用于判断是否出现了 bible 之外的新设定）

## 2. 更新（五个文件全部要处理，没有变化也要确认一遍）
1. **state/ledger.md**
   - "全局"表：最近同步章节改为 XXX；更新故事内时间、所在地、当前卷/篇。
   - "人物状态"表：每个出场角色一行（首次出场就新增一行）；更新位置、伤势、持有物、当前情绪、最近与谁发生了什么（只保留最近 1–2 件）、知道哪些秘密（累积，不删）。
   - 未出场角色的行保持不变。
2. **state/foreshadow.md**：新埋的伏笔加行（状态"未回收"，计划回收章节取自章节卡或卷大纲，没有就写"待定"）；本章回收的改为"已回收"。
3. **state/questions.md**：新提出的悬念加行（状态"开放"）；部分揭晓的改"部分回答"；完全揭晓的改"已回答"。
4. **state/gags.md**：本章用到的每个梗——已有则在"使用章节列表"追加 XXX、次数 +1；没有则新增。状态按次数更新：1 次=活跃，2–3 次=需升级，4 次=退休。
5. **state/summaries.md**：在文件末尾追加
   ```
   ## 第XXX章 章名
   200 字以内摘要：发生了什么、谁知道了什么、留下了什么钩子。不写评价。
   ```

## 3. 不得做的事
- 不得修改 bible/。如果定稿正文出现了 bible 里没有的新设定（新地名、新能力、新规则、新的人物过往）：不写入 bible，用【冲突报告】格式列出，问作者是否要补进 bible。
- 不得修改正文与章节卡。

## 4. 校验
运行 `python3 tools/novel.py health`，确认：梗次数栏与章节列表一致、状态标注正确。有 ⚠️ 的条目要么修正，要么在回复中说明。

## 5. 回复作者：差异清单
```
第XXX章已同步

### ledger
- 变化：洛克 位置 A → B；……
- 新增：……
### foreshadow
- 新增：……（计划 ch___ 回收）
- 关闭：……
### questions
- 新增 / 部分回答 / 已回答：……
- 当前开放悬念：N 个（理想 3–5）
### gags
- ……：第 N 次使用 → 状态
### summaries
- 已追加第 XXX 章摘要（___ 字）

### 计划与实际不符（章节卡 vs 定稿）
- ……（无则写"无"）
### 待作者决定
- ……（新设定、超期伏笔等，无则写"无"）
```
