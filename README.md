# AI 协作长篇小说生产系统

一部约 30 万字、4 卷、约 110 章的幽默西幻网文（番茄小说）的写作工作台。

**分工：** 你（作者）负责品味、关键决策和关键章节精修；Claude 负责产能、结构和一致性。
**核心思路：** 把 AI 写长篇最容易崩的地方（忘设定、人设漂移、伏笔丢失、梗用烂、节奏塌陷）交给外部文件兜底，而不是指望 AI 记住整本书。

---

## 一、命令一览

在本目录启动 Claude Code 后，输入斜杠命令：

| 命令 | 一句话说明 |
|---|---|
| `/cards 41-50` | 生成第 41–50 章的章节卡，给你一张汇总表审核 |
| `/write 47` | 按章节卡写第 47 章正文，并自检字数、兑现度、AI 腔、梗重复（不动 state/） |
| `/review 47` | 两个独立子智能体（挑剔读者 + 连续性审计员）审稿，写入 reviews/，给出弃书风险评分和 3 条修改建议 |
| `/sync 47` | 你确认第 47 章定稿后，更新全部状态账本，列出差异清单 |
| `/audit 41-50` | 10 章体检：一致性、节奏、账本健康，给出下 10 章最该调整的 3 件事 |
| `/dash` | 项目仪表盘：进度、字数、悬念、伏笔、梗排行、下一步该敲什么命令 |

> `/dash` 原定名为 `/status`，但它和 Claude Code 内置的 `/status`（看版本和账号）重名，会被遮蔽，所以改名。

## 二、每天的标准工作流

```
          ┌───────────── 前一天 /write 出来的初稿 ─────────────┐
          ▼                                                     │
   ① /review N  →  ② 你精修第 N 章  →  ③ /sync N  →  ④ /write N+1
   读审稿记录        在 chapters/ 里直接改     账本更新         写下一章初稿
   决定改什么        改完即视为定稿            看差异清单        看三五行自检
```

1. **审稿**：`/review N`。打开 `reviews/chNNN-review.md`，看弃书风险评分和"最重要的 3 条"。在文末"作者决定"里写下你采纳什么、不采纳什么（这是给未来的你和 AI 看的决策记录）。
2. **精修**：直接改 `chapters/chNNN.md`。关键章节（开篇、卷末、关系转折）建议亲自重写核心段落；满意的段落可以复制到 `style/anchors/` 当风格锚点。
3. **同步**：`/sync N`。看差异清单，重点看"计划与实际不符"和"待作者决定"两节。**不 sync 的章节不算完成**，下一章会读到过期的状态。
4. **写下一章**：`/write N+1`。如果没有章节卡了，先 `/cards`。

不确定下一步做什么，就敲 `/dash`，它会告诉你。

## 三、每 10 章要做的事

1. `/audit 起-止`（例如 `/audit 41-50`），读体检报告。
2. 根据"下一个 10 章最该调整的 3 件事"，决定要不要调整卷大纲或后续章节卡。
3. `/cards` 生成下 10 章的章节卡，**认真审汇总表**——这是你掌控全书方向成本最低的地方：改一张卡只要一句话，改一章正文要一小时。
4. 顺手看一眼 `state/gags.md`：哪些梗快退休了，有没有该引入的新组合。
5. 把这 10 章里你最满意的对白补进角色档案的"原文样本"（需要你授权 Claude 改 bible，或你自己改）。

## 五、辅助脚本（也可以自己在终端用）

```bash
python3 tools/novel.py count 41-50       # 各章字数是否在 2500–3000
python3 tools/novel.py lint 47           # 扫描 AI 腔（规则在 style/banned.md 最后一节，可自行追加）
python3 tools/novel.py check-cards 41-50 # 章节卡是否违反节奏规则
python3 tools/novel.py health            # 悬念数、超期伏笔、梗次数
python3 tools/novel.py stats             # 仪表盘原始数据
```

## 六、几条值得记住的规则

- **没有章节卡，不写正文；没有 /sync，章节不算完成。**
- **上层决定下层**：内核 → 设定 → 结构 → 章节卡 → 正文。Claude 发现冲突会停下来给你【冲突报告】和选项，等你决定。
- **写审分离**：审稿的子智能体是全新上下文，看不到写作者的意图（critic 连章节卡都不看），所以它的评价接近真实读者。
- **梗的寿命**：同一个梗第 3 次必须升级或变形，最多用 4 次。
- **尺度**：好色只写"想"和"翻车"，不写"做"。
